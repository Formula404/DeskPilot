## 2026-07-21 任务执行时读取全局最新页面导致目标漂移

**现象**

用户在标签页 A 提交“总结当前页面”后切换到标签页 B，旧链路会在真正执行工具时重新读取活动页或数据库最新一条浏览器上下文，可能错误处理 B；并发网页任务也存在互相串页风险。

**根因**

前端只提交消息，`context_id` 虽进入 Agent state，但执行节点和浏览器工具没有按它读取；浏览器桥接命令默认目标始终为活动标签页。Overlay 位于前台时，Windows 前台窗口采集还可能误把 DeskPilot 自身当成用户目标。

**解决方案**

- 提交时创建不可变 `ContextSnapshot`，冻结 session、窗口、tab、URL、选区和附件引用，并把快照 ID 持久化到 `task_runs`。
- 浏览器命令强制发送快照绑定的 `tab_id`，返回后同时校验 tab 与 URL；不一致时返回 `BROWSER_TARGET_CHANGED`，禁止退回全局最新页面。
- Agent 增加 `load_task`、`load_snapshot`、`build_context`，所有跨域上下文统一由 `ContextBuilder` 按 intent 和 Token 预算装配。
- Windows 采集发现前台是 DeskPilot Overlay 时，沿 Z-order 选择其后的首个真实用户窗口。
- 增加并发任务隔离、目标漂移、快照绑定、预算、指代解析与 Secret 门禁测试。

**涉及文件**

- `backend/app/context/`
- `backend/app/agent/`
- `backend/app/browser/bridge.py`
- `backend/app/db/connection.py`
- `backend/app/db/repository.py`

- `browser-extension/src/background.ts`
- `frontend/src/api/client.ts`
- `frontend/src/views/Overlay.tsx`
- `backend/tests/test_context_engineering.py`

**验证方式**

- `uv run pytest`（79 passed）

**后续注意**

任何网页、窗口或附件工具都不得把“当前/最新”当成生产任务目标。新增目标类型时必须在提交阶段冻结身份、在执行阶段定向访问并校验身份；快照过期只能刷新同一目标，不能静默选择替代目标。

## 2026-07-21 通用对话进度不可见与恢复任务阻塞关闭

**现象**

通用对话直接等待模型响应，等待期间 SSE 没有步骤事件，前端看起来像卡住；服务关闭时会等待启动恢复的长任务自然完成。上下文压缩还会把 `Dr.` 等英文缩写误判为段落边界，工具执行失败后审计记录会丢失已解析参数。

**根因**

- `general_chat` 没有执行与工具节点一致的步骤发布和持久化流程。
- lifespan 对恢复任务只做 `gather`，没有先发出取消。
- 压缩逻辑使用包含英文句点的宽泛正则，并未对超长单段施加硬上限。
- 工具异常处理无条件用原始 JSON 字符串覆盖 `arguments`。

**解决方案**

- 通用对话在模型请求前发布 `task.step.started`，完成或失败后持久化并发布相应步骤。
- 关闭时先取消未完成的恢复任务，再用 `gather(return_exceptions=True)` 回收。
- 只使用空行和无歧义的中英文强终止符切块，保留缩写、小数和 URL，并裁剪超长单段。
- 仅在参数解析尚未成功时记录 `raw_arguments`；执行期异常保留结构化参数。
- 会话消息与快照原本已有 `ON DELETE CASCADE`；另增加显式删除以兼容可能缺失外键的旧数据库。

## 2026-07-08 Overlay 点击悬浮球后首帧闪烁

**现象**

点击悬浮球打开 overlay 时，UI 会先全部出现，再消失，然后才播放输入框上滑和胶囊按钮弹出的入场动画。

**根因**

Tauri overlay 窗口是隐藏但已挂载的 React 视图。此前 `useGSAP` 在隐藏状态下已经播放完入场动画，导致 DOM 上残留可见 inline style。下次窗口 `show()` 时浏览器先绘制上一轮可见状态，然后 GSAP 再把元素设回透明并播放动画，形成首帧闪烁。

**解决方案**

- 为 overlay 入场元素添加 CSS 初始隐藏态。
- Tauri 环境下组件 mount 时只执行隐藏态 reset，不主动播放入场动画。
- 入场动画改由窗口 focus 后触发。
- `resetOverlayMotionTargets()` 关闭后不再把输入框/胶囊按钮 reset 成可见，而是 reset 成下一次入场前的隐藏态。

**涉及文件**

- `frontend/src/views/Overlay.tsx`
- `frontend/src/styles/components.css`

**验证方式**

- `npm run build`
- 手动点击悬浮球，确认 overlay 不再出现“全部出现 -> 消失 -> 入场”的首帧闪烁。

**后续注意**

Tauri 多窗口里“隐藏窗口仍然挂载”是常态。任何入场动画如果依赖初始透明态，都要确保隐藏窗口期间不会提前播完并留下可见 inline style。

## 2026-07-08 Overlay 入场动画被 focus 事件重复触发

**现象**

点击悬浮球后 overlay 会出现一次短暂闪动，像是出现、消失、再真正进入。

**根因**

入场动画同时被 `useGSAP` 初次执行和 `onFocusChanged` 触发。第二次触发会再次执行 `gsap.set(... autoAlpha: 0, y: ...)`，把已经出现的输入框重新放回底部并设为透明。

**解决方案**

- 增加 `openTimelineRef` 保存当前入场 timeline。
- 如果入场 timeline 仍 active，后续 focus 触发直接忽略。
- timeline complete / reset / unmount 时清理 `openTimelineRef`。

**涉及文件**

- `frontend/src/views/Overlay.tsx`

**验证方式**

- `npm run build`
- 连续点击悬浮球打开 overlay，确认入场动画只播放一次。

**后续注意**

窗口 focus、mount、状态变化都可能触发动效。任何打开动画都应有“正在播放”保护，避免重复 `set` 初始态。

## 2026-07-08 悬浮球偶发消失

**现象**

使用过程中悬浮球会自己消失，用户无法再次打开 overlay。

**根因**

打开 overlay 时悬浮球会被 `hide()`，恢复完全依赖 overlay 关闭链路调用 `restoreFloatingBall()`。如果某次关闭、失焦或窗口状态更新没有完整走到恢复逻辑，悬浮球会长期 hidden。

**解决方案**

- 在悬浮球窗口内增加空闲自愈守护：当 overlay 不可见而悬浮球自身 hidden 时，主动 `show()`。
- `restoreFloatingBall()` 增加多次延迟检查，覆盖 Tauri 可见状态更新延迟。

**涉及文件**

- `frontend/src/views/FloatingBall.tsx`
- `frontend/src/views/windowActions.ts`

**验证方式**

- `npm run build`
- 手动打开/关闭 overlay，多次失焦后确认悬浮球能恢复。

**后续注意**

跨窗口 hide/show 不应只依赖单一关闭路径。关键入口窗口需要自愈或状态守护。

### 2026-07-21 复发记录

**现象**

非模态浮窗改造后，打开并关闭一次 overlay，overlay 与悬浮球会一起消失。

**根因**

关闭链路先执行 `overlay.hide()`，再异步调用 `restoreFloatingBall()`。Windows 隐藏 WebView 后会暂停该窗口中的 JavaScript，导致后续恢复悬浮球的 Promise 和延迟检查可能无法继续执行。

首次时序修复后继续复测发现，GSAP 退场还会在隐藏但未卸载的 overlay DOM 上保留 `opacity: 0` 和 `visibility: hidden`。第二次原生窗口虽然成功显示，React 组件不会重新挂载，入场动画也不会自动重播，因此窗口内容完全透明；悬浮球随后正常隐藏，视觉上表现为两个窗口一起消失。

**解决方案**

- 调整跨窗口关闭顺序：先直接 `show()` 悬浮球，再隐藏 overlay。
- 调整跨窗口打开顺序：先显示并聚焦 overlay，再隐藏悬浮球，避免调用方窗口提前暂停。
- overlay 打开失败时，由仍处于活动状态的调用链直接隐藏 overlay 并显示悬浮球，不再依赖隐藏窗口内的延迟任务。
- 关闭时将 overlay 内部形态重置为快速输入，保证第二次唤起的窗口尺寸与内容一致。
- 悬浮球每次显示 overlay 后向目标窗口发送 `overlay-open-request`，overlay 收到事件后强制恢复快速输入形态并重播入场动画，清除上一次退场留下的透明状态。
- Tauri 环境挂载时先将面板设为透明，避免 `show()` 到打开事件之间出现不透明首帧；焦点回调仅在检测到面板仍透明时补进入场动画，作为跨窗口事件丢失时的回退。
- 移除两个同时修改 panel 透明度和 transform 的独立 tween，形态变化只动画内部内容，面板入场由单一 timeline 持有。
- 恢复悬浮球改为关闭 overlay 前同步重试并检查 `isVisible()`；多次失败时保留 overlay，避免两个入口同时消失。
- 移除浮窗四周透明 padding，避免透明 WebView 边缘在 Windows 上呈现黑边。
- overlay 的三种形态统一定位到当前显示器工作区底部中央、任务栏上方。

**涉及文件**

- `frontend/src/views/windowActions.ts`
- `frontend/src/styles/components.css`

**验证方式**

- `npm run build`
- 连续打开、关闭 overlay，确认悬浮球每次都在 overlay 隐藏前恢复。
- 连续打开、关闭至少 5 次，确认每次重新打开都会收到跨窗口事件并恢复可见内容。
- 模拟打开事件未到达，确认 overlay 获得焦点时只在内容仍透明的情况下补播入场动画。
- 检查快速输入、对话和执行控制条三种尺寸均贴合原生窗口边界并位于任务栏上方中央。

**后续注意**

不要在隐藏 Tauri WebView 后依赖该窗口继续完成关键跨窗口操作；恢复入口窗口必须发生在当前窗口隐藏之前。

## 2026-07-08 入场动画不可打断

**现象**

用户误点击悬浮球打开 overlay 后，如果想马上退出，必须等入场动画全部播放完成。入场过程中点击空白或按 Esc 不会立即关闭。

**根因**

`shouldIgnoreClose` 用时间窗口屏蔽所有关闭请求，原本是为了避免 Tauri focus 抖动导致刚打开就被 blur 关闭，但也误拦截了用户主动关闭。

**解决方案**

- `useWindowLifecycle` 增加关闭原因：`manual`、`escape`、`blur`。
- 入场保护只忽略 `blur`，不忽略用户点击空白或 Esc。
- 退场动画开始时 kill 当前入场 timeline 和相关 tweens，从当前动画状态直接接退场。

**涉及文件**

- `frontend/src/hooks/useWindowLifecycle.ts`
- `frontend/src/views/Overlay.tsx`

**验证方式**

- `npm run build`
- overlay 输入框尚未完全入场时点击空白或按 Esc，确认可以立即退场。

**后续注意**

浮窗应用的动效必须可打断。系统事件保护和用户主动操作不能混为一谈。

## 2026-07-08 玻璃 UI 中间层过深显脏

**现象**

Overlay 中输入框和胶囊按钮的玻璃材质中间区域接近黑色，视觉上显得脏。用户明确指出不是图标/品牌蓝色问题。

**解决方案**

- 恢复图标/按钮品牌蓝色，不改变 accent 语义。
- 仅提亮玻璃背景的中间暗层和底色层，改为更干净的蓝灰透明层。
- 同步提亮任务状态 pill、step、empty state 的玻璃底色。

**涉及文件**

- `frontend/src/styles/components.css`
- `frontend/src/styles/tokens.css`

**验证方式**

- `npm run build`
- 对照 overlay 截图检查输入框和胶囊按钮中部不再接近黑色。

**后续注意**

调整视觉颜色前要先区分“品牌色/图标色”和“材质底色”。不要为了解决玻璃发脏误改 icon 或 action 色。

## 2026-07-21 知识库并发覆盖与本地接口安全边界不足

**现象**

并发编译、重复采集或同时审核时可能产生重复任务、孤立快照或旧提案覆盖新编辑；完整备份恢复若接受恶意 ZIP 路径可能写出知识库目录；浏览器桥接 WebSocket 未校验 Origin。

**根因**

知识库写操作此前只有进程内流程判断，没有跨线程/进程的原子资源锁；Proposal 未绑定目标内容版本；备份 manifest 未约束成员路径；本地服务默认信任所有 Host 和 WebSocket Origin。

**解决方案**

- 增加 SQLite 租约锁，对来源采集、编译、页面写入、审核和恢复按资源串行化。
- Proposal 持久化目标 Note SHA-256 和来源快照 ID，审核前执行乐观并发校验。
- 备份恢复验证每个成员的 SHA-256、相对安全路径和非符号链接属性。
- HTTP 增加 Trusted Host，浏览器桥接仅允许配置来源、Tauri 和 Chrome 扩展来源。
- 增加 24 路重复采集和 8 路并发审核测试。

**涉及文件**

- `backend/app/knowledge/locking.py`
- `backend/app/knowledge/compiler.py`
- `backend/app/knowledge/source_service.py`
- `backend/app/knowledge/backup.py`
- `backend/app/main.py`
- `backend/app/api/routes_browser.py`
- `backend/tests/test_knowledge_security.py`

**验证方式**

**后续注意**

新增任何会修改知识文件、索引或 Profile 成员关系的入口，都必须声明资源锁键并同时验证数据库与文件两侧的一致性；导入归档格式不得直接信任成员路径。

## 2026-07-21 非模态浮窗三期 — 多形态面板（Quick / Conversation / HUD）

**现象**

将全屏浮窗重写为紧凑非模态面板（快速输入/对话/执行控制条三种形态），引入 Tauri 窗口动态尺寸切换和跨窗口事件通讯。代码审查发现 8 项问题。

**涉及文件**

- `frontend/src/views/windowActions.ts`
- `frontend/src/styles/components.css`
- `frontend/src-tauri/tauri.conf.json`

**发现列表**

1. HUD 形态下失败/取消任务仍显示绿色勾（Overlay.tsx:292）
   - 严重：高
   - `running ? <LoaderCircle/> : <CheckCircle2/>` 仅在 running 时显示加载图标，非 running 一律显示绿勾。mode 为 "failed"/"cancelled" 时 statusLabel 虽显示正确文字，但图标与状态冲突。
   - 修复：用 `mode === "completed"` 条件区分，失败/取消使用 XCircle 或 AlertCircle。

2. startNewConversation 未清除 streamError（Overlay.tsx:273）
   - 严重：高
   - SSE 断开后 streamError 被设置。用户点"新对话"仅清除 actionError，streamError 残留，新对话中仍显示"任务事件连接异常"。
   - 修复：startNewConversation 中增加 `setStreamError(null)`。

3. 窗口显示先于入场动画（windowActions.ts:95-96 / Overlay.tsx:130）
   - 严重：中
   - `showOverlayWindow()` 先调 `overlay.show()` 再 `emitTo("overlay-open-request")`。监听器将 `playOpenMotion()` 包在 `requestAnimationFrame` 中。窗口先以 CSS 默认不透明度 (1) 可见，约 16-33ms 后 GSAP 才施加 autoAlpha:0 开始淡入，产生闪烁。
   - 修复：emitTo 提前到 overlay.show() 之前发出，或 show 前预先设置 CSS opacity: 0。

4. 入场 GSAP timeline 被形态过渡 fromTo 覆盖（Overlay.tsx:146）
   - 严重：中
   - 第二个 useGSAP（依赖 `[shape, reduceMotion]`）在挂载时运行。`gsap.fromTo()` 默认 `immediateRender: true` 且因全局 `overwrite: "auto"` 覆盖了 timeline 中对同一 panel 的子动画。panel 从 autoAlpha:0.72 而非 0 开始动画。当前因挂载时窗口隐藏而未产生可见故障，但仍为潜在 bug。
   - 修复：第二个 useGSAP 增加早期返回守卫，或改用 timeline 统一管理。

5. restoreFloatingBall 轮询重试丢失（windowActions.ts:34-41）
   - 严重：中
   - 原 `restoreFloatingBall()` 实现了最多 5 次轮询（0/120/360/900/1800ms）加版本号守卫以应对 Tauri 窗口管理器竞争。新代码内联为单次 `await floatingBall?.show()` 且无重试，`restoreFloatingBall` 函数变为死代码。
   - 修复：保留轮询重试逻辑或确认 Tauri 版本已不需要。

6. 点击外部关闭行为完全移除（Overlay.tsx:183/186）
   - 严重：中
   - 旧代码通过 `onMouseDownCapture` 检查点击目标和 `closeOnBlur: true` 实现遮挡区域关闭。新代码设置 `closeOnBlur: false` 且删除 `onMouseDownCapture`，唯一的关闭路径只剩 X 按钮。
   - 修复：恢复外部关闭机制（点击非交互区域或窗口失焦时关闭）。
