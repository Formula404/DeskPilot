# DeskPilot GSAP 精细动效设计计划

## 1. 目标

DeskPilot 的所有动效统一基于 GSAP 实现，不再采用 CSS-only 作为第一优先方案。CSS 只负责静态样式、初始可见性、`will-change` 和无障碍降级；动效编排、状态切换、入场退场、循环反馈、列表事件变化全部交给 GSAP timeline / tween。

本计划覆盖当前应用完整使用流程：

```text
应用启动
  -> 悬浮球出现
  -> hover / active / 拖拽 / 右键菜单
  -> 点击悬浮球打开 Overlay
  -> 上下文识别
  -> 推荐操作与命令输入
  -> 创建任务
  -> SSE 任务事件持续流入
  -> 等待确认 / 执行中 / 完成 / 失败 / 取消
  -> 用户继续输入或关闭 Overlay
  -> 回到悬浮球

右键菜单
  -> 设置窗口
  -> 设置导航切换
  -> 配置项反馈
  -> 关闭窗口
```

动效定位：

- 入口响应必须快，避免桌面工具迟滞感。
- 任务过程必须清晰，避免用户不知道 AI 正在做什么。
- 状态变化必须可辨识，但不能用持续闪烁制造噪音。
- 所有窗口退场都要先播放 timeline，再调用 Tauri hide。

## 2. GSAP 技术基线

### 2.1 依赖

前端需要引入：

```bash
cd frontend
npm install gsap @gsap/react
```

目标依赖：

```json
{
  "dependencies": {
    "gsap": "^3.x",
    "@gsap/react": "^2.x"
  }
}
```

### 2.2 React 接入规范

所有组件级动效使用 `@gsap/react` 的 `useGSAP()`。

要求：

- 在前端入口或动画工具模块中执行 `gsap.registerPlugin(useGSAP)`。
- 每个动效组件使用 `scope` ref，禁止无作用域全局选择器。
- 事件回调中创建的 tween 使用 `contextSafe()` 包裹。
- 组件卸载时依赖 `useGSAP` 自动 cleanup；手动创建的长生命周期 timeline 存入 ref 并在 cleanup kill。

示例结构：

```ts
import gsap from "gsap";
import { useGSAP } from "@gsap/react";

gsap.registerPlugin(useGSAP);

const rootRef = useRef<HTMLElement | null>(null);

useGSAP(
  () => {
    const tl = gsap.timeline({
      defaults: { duration: 0.18, ease: "power2.out" }
    });

    tl.from(".motion-item", {
      autoAlpha: 0,
      y: 8,
      stagger: 0.03
    });
  },
  { scope: rootRef }
);
```

### 2.3 动效工程目录建议

建议新增：

```text
frontend/src/motion/
  constants.ts
  timelines.ts
  useReducedMotion.ts
  useWindowMotion.ts
  taskMotion.ts
  selectors.ts
```

职责：

| 文件 | 职责 |
|---|---|
| `constants.ts` | 统一 duration、ease、stagger、z-motion 参数 |
| `timelines.ts` | 通用入场、退场、shake、pulse、status timeline |
| `useReducedMotion.ts` | `gsap.matchMedia()` / reduced motion 封装 |
| `useWindowMotion.ts` | Tauri hide/show 前后的 timeline 编排 |
| `taskMotion.ts` | 任务事件新增、状态转换、列表溢出动画 |
| `selectors.ts` | 稳定 data-motion selector，避免依赖样式 class |

### 2.4 稳定选择器规范

动效目标使用 `data-motion`，不要依赖视觉 class。

示例：

```tsx
<main ref={rootRef} className="overlay-stage" data-motion="overlay">
  <div className="suggestion-row" data-motion="suggestions">
    <button data-motion="suggestion-item" />
  </div>
  <form data-motion="composer" />
</main>
```

原因：

- class 后续可能因样式重构变化。
- GSAP selector 需要长期稳定。
- data selector 能明确表达动画边界。

### 2.5 统一运动参数

建议参数：

```ts
export const motion = {
  duration: {
    micro: 0.08,
    fast: 0.12,
    base: 0.18,
    panel: 0.24,
    window: 0.28,
    loop: 1.2
  },
  ease: {
    out: "power2.out",
    in: "power2.in",
    inOut: "power3.inOut",
    sharp: "power4.out",
    softBack: "back.out(1.18)",
    none: "none"
  },
  stagger: {
    tight: 0.025,
    normal: 0.04,
    loose: 0.065
  }
};
```

使用约束：

- 主要入场使用 `power2.out`。
- 关闭退场使用 `power2.in`。
- 悬浮球、菜单这种小物件可以使用低强度 `back.out(1.18)`。
- 不使用大幅 `elastic` 或 `bounce`。
- 持续动画使用 `ease: "none"` 或非常轻的 `sine.inOut`。

### 2.6 性能规范

GSAP 动画属性优先级：

```text
优先：x / y / scale / rotation / autoAlpha
谨慎：filter / boxShadow / backgroundColor
避免：width / height / top / left / margin / padding
```

要求：

- 进入动画前使用 `gsap.set()` 写入初始 transform，避免闪烁。
- 退场使用 `autoAlpha: 0`，让元素不可见时不拦截点击。
- 对频繁交互目标使用 `overwrite: "auto"`。
- 对拖拽或鼠标跟随类动效使用 `gsap.quickTo()`。
- 页面隐藏、窗口 hide、任务完成后 kill 循环 timeline。

### 2.7 Reduced Motion

必须用 `gsap.matchMedia()` 处理：

```ts
const mm = gsap.matchMedia();

mm.add(
  {
    reduceMotion: "(prefers-reduced-motion: reduce)",
    normalMotion: "(prefers-reduced-motion: no-preference)"
  },
  (context) => {
    const { reduceMotion } = context.conditions;
    // reduceMotion 时将 duration 设为 0 或跳过循环 timeline
  }
);
```

策略：

- reduce motion 下保留状态颜色变化。
- 取消呼吸、旋转、扫光、脉冲。
- 入场退场 duration 置为 0 或 0.01。

## 3. 全局 Timeline 架构

### 3.1 命名规范

每个模块维护可控 timeline：

| Timeline | 所属模块 | 用途 |
|---|---|---|
| `floatingIntroTl` | FloatingBallView | 悬浮球启动 / 恢复 |
| `floatingIdleTl` | FloatingBallView | 空闲呼吸 |
| `floatingStatusTl` | FloatingBallView | 执行中 / 等待确认 / 失败状态 |
| `contextMenuOpenTl` | ContextMenuView | 菜单打开 |
| `contextMenuCloseTl` | ContextMenuView | 菜单关闭 |
| `overlayOpenTl` | OverlayView | Overlay 入场 |
| `overlayCloseTl` | OverlayView | Overlay 退场 |
| `contextDetectTl` | OverlayView | 上下文识别 |
| `composerSubmitTl` | CommandComposer | 提交反馈 |
| `composerModeTl` | CommandComposer | 发送 / 停止 / 创建中切换 |
| `taskPanelIntroTl` | TaskExecutionPanel | 面板入场 |
| `taskEventInTl` | TaskExecutionPanel | 新事件入场 |
| `taskStatusTl` | TaskExecutionPanel | 状态胶囊变化 |
| `approvalTl` | ApprovalPanel | 权限确认入场 / 退场 |
| `settingsIntroTl` | SettingsView | 设置窗口入场 |
| `settingsSwitchTl` | SettingsView | 设置内容切换 |

### 3.2 窗口关闭策略

所有 Tauri 窗口关闭必须改为：

```text
用户触发关闭
  -> 播放 close timeline
  -> timeline onComplete
  -> 调用 Tauri hide
  -> 必要时恢复 floating-ball
```

禁止直接在点击事件里调用 `hideCurrentWindow()`，否则无法播放退场。

建议新增：

```ts
async function closeWithTimeline(tl: gsap.core.Timeline, afterClose: () => Promise<void>) {
  tl.eventCallback("onComplete", () => void afterClose());
  tl.restart();
}
```

## 4. 模块一：悬浮球

### 4.1 启动 / 恢复 Timeline：`floatingIntroTl`

触发：

- 应用启动显示 `floating-ball`。
- Overlay 关闭后恢复悬浮球。

时间线：

```text
0.00s orb autoAlpha 0 -> 1
0.00s orb scale 0.88 -> 1
0.00s orb x 12 -> 0
0.05s logo scale 0.82 -> 1
0.08s status-ring autoAlpha 0 -> 1
```

GSAP 设计：

```ts
gsap.timeline({ defaults: { ease: "power2.out" } })
  .fromTo("[data-motion='floating-orb']",
    { autoAlpha: 0, scale: 0.88, x: 12 },
    { autoAlpha: 1, scale: 1, x: 0, duration: 0.2 }
  )
  .from("[data-motion='orb-logo']",
    { autoAlpha: 0, scale: 0.82, duration: 0.16 },
    "<0.04"
  )
  .from("[data-motion='status-ring']",
    { autoAlpha: 0, scale: 0.94, duration: 0.18 },
    "<0.04"
  );
```

如果悬浮球吸附在左侧，`x` 使用 `-12`；右侧使用 `12`。

### 4.2 空闲呼吸 Timeline：`floatingIdleTl`

触发：

- 启动入场结束 3 秒后。
- 当前无任务、无菜单、无 Overlay。

动效：

- 只动外圈与微弱高光，不动悬浮球主体尺寸。

```ts
gsap.timeline({ repeat: -1, yoyo: true, defaults: { ease: "sine.inOut" } })
  .to("[data-motion='status-ring']", {
    autoAlpha: 0.72,
    scale: 1.025,
    duration: 1.4
  });
```

停止条件：

- hover。
- 拖拽。
- 右键菜单打开。
- Overlay 打开。
- 进入任务状态。

### 4.3 Hover / Active

触发：

- pointer enter。
- pointer leave。
- pointer down / up。

实现方式：

- 使用 `contextSafe()` 包裹事件回调。
- 使用 `gsap.to()`，`overwrite: "auto"`。

参数：

| 状态 | target | vars |
|---|---|---|
| hover in | orb | `scale: 1.045, duration: 0.12, ease: "power2.out"` |
| hover out | orb | `scale: 1, duration: 0.14, ease: "power2.out"` |
| press | orb | `scale: 0.965, duration: 0.08` |
| release | orb | `scale: 1.035 -> 1, duration: 0.14` |

### 4.4 拖拽状态

触发：

- 鼠标移动超过当前代码中的 4px 阈值并调用 `startDragging()`。

GSAP 反馈：

```text
drag-start:
  orb scale -> 0.96
  orb autoAlpha -> 0.82
  status-ring autoAlpha -> 0

drag-end:
  orb autoAlpha -> 1
  orb scale -> 1
  status-ring autoAlpha -> 1
```

后续如果实现自动吸附：

- 位置值由 Tauri 计算。
- 视觉反馈用 `x` 局部轻微回弹，不直接动画窗口坐标。

### 4.5 任务状态反馈：`floatingStatusTl`

任务状态来自 `taskStore`：

| 状态 | 动效 |
|---|---|
| running | 外圈连续旋转，logo 轻微明暗变化 |
| waiting-approval | 黄色点 `scale 0.85 -> 1.12` 脉冲 |
| completed | 绿色环扫过 0.45s，然后恢复 idle |
| failed | 红色点淡入并停留 |
| cancelled | 灰色状态点淡入 0.5s 后恢复 |

要求：

- 每次状态变化先 `floatingStatusTl?.kill()`。
- 创建新的状态 timeline。
- 任务完成或取消后回到 idle 呼吸。

## 6. 模块三：Overlay

### 6.1 打开 Timeline：`overlayOpenTl`

触发：点击悬浮球，overlay 窗口 show 后。

分层目标：

- `overlay-stage`
- `composer-area::before` 当前是伪元素，GSAP 不能直接可靠控制；建议改为真实 DOM：`data-motion="overlay-gradient"`。
- `suggestion-row`
- `suggestion-item`
- `command-composer`
- `composer-spark`

推荐 DOM 调整：

```tsx
<main data-motion="overlay">
  <div data-motion="overlay-gradient" />
  <section data-motion="workspace">
    ...
  </section>
</main>
```

时间线：

```text
0.00s overlay autoAlpha 0 -> 1
0.00s overlay-gradient autoAlpha 0 -> 1, y 24 -> 0
0.06s suggestion-row autoAlpha 0 -> 1
0.08s suggestion-item autoAlpha 0 -> 1, y 12 -> 0, stagger 0.035
0.13s command-composer autoAlpha 0 -> 1, y 18 -> 0, scale 0.985 -> 1
0.18s composer-spark rotation -18 -> 0, scale 0.85 -> 1
0.22s focus input
```

总时长：0.32s 内。

GSAP 参数：

```ts
const tl = gsap.timeline({
  defaults: { ease: "power2.out" },
  onComplete: () => inputRef.current?.focus()
});

tl.fromTo("[data-motion='overlay']",
  { autoAlpha: 0 },
  { autoAlpha: 1, duration: 0.14 }
)
  .from("[data-motion='overlay-gradient']",
    { autoAlpha: 0, y: 24, duration: 0.24 },
    0
  )
  .from("[data-motion='suggestion-item']",
    { autoAlpha: 0, y: 12, duration: 0.18, stagger: 0.035 },
    0.08
  )
  .from("[data-motion='command-composer']",
    { autoAlpha: 0, y: 18, scale: 0.985, duration: 0.22 },
    0.13
  )
  .from("[data-motion='composer-spark']",
    { autoAlpha: 0, rotation: -18, scale: 0.85, duration: 0.16 },
    0.18
  );
```

### 6.2 关闭 Timeline：`overlayCloseTl`

触发：

- Esc。
- 点击空白区域。
- 关闭按钮。

时间线：

```text
0.00s task-side-panel autoAlpha -> 0, x 8
0.00s suggestion-item autoAlpha -> 0, y 6, stagger 0.015
0.02s command-composer autoAlpha -> 0, y 12, scale 0.99
0.05s overlay-gradient autoAlpha -> 0, y 18
0.10s overlay autoAlpha -> 0
0.18s Tauri hide overlay
0.18s restore floating ball
0.20s floatingIntroTl
```

要求：

- close timeline 播放期间禁用重复关闭。
- 关闭完成前不显示 floating ball，避免两个窗口视觉重叠。

### 6.3 上下文识别 Timeline：`contextDetectTl`

后续接入上下文状态时使用。

状态：

| ContextStatus | 动效 |
|---|---|
| detecting | 徽标点位依次 y -2，循环 |
| browser-ready | 徽标 cross-fade，推荐按钮重排入场 |
| window-ready | 徽标 cross-fade，推荐按钮重排入场 |
| unavailable | 徽标淡入弱提示，默认推荐保留 |
| permission-required | 黄色边框轻扫一次 |

GSAP 实现：

- loading dots 使用 repeating timeline。
- 状态变化时 kill loading timeline。
- 旧状态 label `autoAlpha: 0, y: -4`，新状态 label `autoAlpha: 1, y: 0`。

## 7. 模块四：推荐操作

### 7.1 初始入场

已纳入 `overlayOpenTl`。

每个按钮：

```text
autoAlpha 0 -> 1
y 12 -> 0
scale 0.98 -> 1
stagger 0.035
```

### 7.2 Hover Timeline

每个 button 创建 hover tween：

```ts
gsap.to(button, {
  y: -2,
  scale: 1.012,
  duration: 0.12,
  ease: "power2.out",
  overwrite: "auto"
});

gsap.to(icon, {
  scale: 1.08,
  rotation: -2,
  duration: 0.12,
  overwrite: "auto"
});
```

离开：

```ts
gsap.to([button, icon], {
  y: 0,
  scale: 1,
  rotation: 0,
  duration: 0.14,
  ease: "power2.out",
  overwrite: "auto"
});
```

### 7.3 点击推荐操作 Timeline：`suggestionSelectTl`

触发：点击推荐按钮。

时间线：

```text
0.00s selected button scale 0.98 -> 1
0.02s selected icon rotation -6 -> 0
0.04s non-selected buttons autoAlpha 1 -> 0.38, y 4
0.08s command-composer y -2 -> 0
0.10s send button morph state -> creating
0.16s task panel intro
```

实现细节：

- 第一阶段图标切换不做真正 SVG morph，使用 cross-fade：旧 icon `autoAlpha: 0, scale: 0.85`，新 icon `autoAlpha: 1, scale: 1`。
- 如果用户取消或任务失败后回到 idle，推荐按钮使用 reverse / rebuild timeline 恢复。

### 7.4 推荐操作更新 Timeline：`suggestionRefreshTl`

触发：

- 上下文识别完成。
- 用户切换当前窗口。
- 后续历史偏好更新推荐。

时间线：

```text
old items autoAlpha -> 0, y -6, stagger 0.02
container height locked
new items autoAlpha 0 -> 1, y 8 -> 0, stagger 0.035
container height unlocked
```

注意：

- 更新前读取容器高度，只读一次。
- 更新期间通过固定高度防止布局跳动。
- DOM 更新后再执行新 items 入场。

### 8.3 提交 Timeline：`composerSubmitTl`

触发：Enter 或点击发送。

时间线：

```text
0.00s composer y -2
0.06s composer y 0
0.00s send button scale 0.92
0.08s send button scale 1
0.08s send icon autoAlpha 0, y -4
0.10s clock icon autoAlpha 1, rotation -30 -> 0
0.12s loading loop start
```

创建中循环：

```ts
const loadingTl = gsap.timeline({ repeat: -1, defaults: { ease: "none" } });
loadingTl.to(clockIcon, { rotation: 360, duration: 1.1 });
```

任务创建成功：

- kill loading timeline。
- 切换为 stop icon。
- 进入 task panel intro。

任务创建失败：

- kill loading timeline。
- send button 回到 arrow icon。
- 播放 `composerErrorTl`。

### 8.4 运行中 / 停止按钮 Timeline：`composerModeTl`

状态转换：

```text
arrow -> clock -> stop
stop -> arrow
stop -> disabled stopping -> cancelled
```

实现：

- 三个 icon 同时存在，用 `autoAlpha` + `scale` + `rotation` cross-fade。
- 不在 React 中卸载 icon 后再动画；需要保留可动画节点。

建议 DOM：

```tsx
<span data-motion="send-icon-arrow"><ArrowUp /></span>
<span data-motion="send-icon-clock"><Clock3 /></span>
<span data-motion="send-icon-stop"><Square /></span>
```

### 8.5 错误 Timeline：`composerErrorTl`

触发：

- 空输入提交。
- 创建任务失败。
- 停止任务失败。

动效：

```text
composer x 0 -> -3 -> 3 -> -2 -> 0
status-message autoAlpha 0 -> 1, y 6 -> 0
status-message hold
optional auto dismiss after recovery
```

GSAP keyframes：

```ts
gsap.to("[data-motion='command-composer']", {
  keyframes: [
    { x: -3, duration: 0.04 },
    { x: 3, duration: 0.05 },
    { x: -2, duration: 0.04 },
    { x: 0, duration: 0.05 }
  ],
  ease: "power2.out"
});
```

## 14. 状态机与 GSAP 绑定

### 14.1 Overlay 状态

建议前端状态：

```ts
type OverlayMotionState =
  | "closed"
  | "opening"
  | "idle"
  | "creating"
  | "running"
  | "waiting-approval"
  | "completed"
  | "failed"
  | "cancelled"
  | "closing";
```

状态进入动作：

| from -> to | GSAP 动作 |
|---|---|
| closed -> opening | `overlayOpenTl.restart()` |
| opening -> idle | focus input |
| idle -> creating | `composerSubmitTl.restart()` |
| creating -> running | `taskPanelIntroTl.restart()`, `composerModeTl` to stop |
| running -> waiting-approval | `approvalEnterTl.restart()` |
| running -> completed | `taskCompleteTl.restart()` |
| running -> failed | `taskFailedTl.restart()` |
| running -> cancelled | `taskCancelledTl.restart()` |
| any -> closing | `overlayCloseTl.restart()` |

### 14.2 TaskEvent 绑定

`TaskExecutionPanel` 不应只依赖 CSS animation。建议在 `events.length` 变化时：

1. 找到新增 event 对应 DOM。
2. 调用 `taskEventInTl`。
3. 根据 event type 启动或关闭状态 loop。

需要维护：

```ts
const runningStepLoopsRef = useRef(new Map<string, gsap.core.Timeline>());
const waitingStepLoopsRef = useRef(new Map<string, gsap.core.Timeline>());
```

任务结束时：

```ts
for (const tl of runningStepLoopsRef.current.values()) tl.kill();
for (const tl of waitingStepLoopsRef.current.values()) tl.kill();
```

## 16. 验收标准

### 16.1 GSAP 使用

- 所有入场、退场、状态变化、循环动效均由 GSAP 实现。
- React 组件内使用 `useGSAP()` 或 `gsap.context()`，有明确 scope 和 cleanup。
- 不存在无 scope 的全局 selector 动画。
- 不存在组件卸载后仍运行的 timeline。

### 16.2 主流程

- 点击悬浮球后 Overlay 主内容在 0.32s 内完成入场。
- Overlay 关闭先播放退场，再隐藏 Tauri 窗口。
- 推荐操作、命令输入、任务面板之间的动效有清晰先后关系。
- 创建中、运行中、等待确认、完成、失败、取消状态都有独立 timeline。

### 16.3 任务事件

- 新 SSE 事件使用 GSAP 入场。
- running / waiting 使用可 kill 的循环 timeline。
- completed / failed / cancelled 会停止所有相关循环 timeline。
- 事件超过 7 条时列表不突跳。

### 16.4 设置窗口

- 设置窗口打开、关闭、导航切换都通过 GSAP timeline。
- 内容页切换有退场和入场，不直接闪切。
- Toggle、Select、Input、保存成功都有局部 GSAP 反馈。

### 16.5 性能与无障碍

- 主动画只使用 `x`、`y`、`scale`、`rotation`、`autoAlpha` 为主。
- 长循环 timeline 在窗口隐藏、任务结束、组件卸载时 kill。
- `prefers-reduced-motion: reduce` 下无旋转、脉冲、扫光等持续动画。
- 快速连续 SSE 事件不会造成明显卡顿。

## 18. 风险

- 直接隐藏 Tauri 窗口会截断 GSAP 退场，必须重构关闭流程。
- React 条件渲染会导致退场元素被卸载，需要使用 displayed state 或保留 icon/面板 DOM。
- 任务事件流可能高频到达，要复用 timeline 或 batch 处理，避免每个事件创建过多长期对象。
- 透明窗口上 `filter`、大面积 blur、boxShadow 动画可能较重，优先使用 transform / autoAlpha。
- GSAP timeline 与 CSS transition 同时控制同一属性会冲突，相关属性要交给 GSAP。
