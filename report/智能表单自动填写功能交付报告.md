# DeskPilot 智能表单自动填写功能交付报告

交付日期：2026-07-28

## 交付范围

本次交付完成了“网页表单识别—个人信息增量学习—相似字段匹配—自动填写—个人信息维护”的完整链路。

### 1. 网页表单识别与安全采集

- 浏览器扩展新增 `inspect_form` 结构化命令，识别 `input`、`textarea`、`select`，采集 label、name、id、placeholder、autocomplete、类型、选项和当前值。
- 支持显式 label、ARIA 标签、fieldset/附近标签、帮助文字、所属章节、前后字段关系等多种语义来源。
- 在浏览器端直接排除密码、隐藏、文件、验证码/OTP、令牌以及银行卡/CVV 等支付敏感字段，这些值不会进入后端。
- 每次扫描只生成临时 `dp-field-*` 标识；填写命令只能操作这些白名单标识，不接受任意选择器或脚本。
- 支持两栏/栅格表单中的视觉邻近标签，以及 Ant Design、Element Plus、Semi、Arco 等常见组件库的自定义下拉和单选控件。
- 字段会携带章节、记录序号和关联键，使教育、工作/实习、项目、技能、证书、获奖等多个字段能够作为同一条记录处理。
- 每次页面文档生成独立实例 ID；填写前同时核对标签页、URL、文档实例和字段当前值，页面刷新、跳转或内容变化都会阻止旧预览继续写入。

### 2. 可增长的个人信息库

- 新增 `personal_info_fields` 持久化模型，包含分类、稳定字段键、显示名称、值、别名、来源、置信度、状态和更新时间。
- 默认分类：身份信息、联系方式、地址信息、工作与实习、教育经历、项目经历、技能、证书、获奖经历、常用问答、偏好设置、其他信息。
- 明确指令或“记住当前表单”产生 `confirmed` 信息；普通聊天中识别到的姓名、邮箱、手机、公司、职位、学校等先进入 `proposed` 待确认状态。
- 待确认信息不会覆盖已经确认的信息。
- 新增 `form_templates` 与 `form_fill_memories`，按站点、归一化动态路径和字段语义签名记忆表单结构、字段映射、站点专用值、忽略/暂缓规则及经历偏好。
- 新增 `personal_info_records` 与 `personal_info_record_fields`：教育、工作/实习、项目、技能、证书、获奖和常用问答均可保存多条父记录与子字段；常用问答支持同一问题的多个答案版本。
- 不同网站确认过的字段别名采用累积合并，不会因下一次记忆覆盖旧关系。

### 3. 语义匹配与填写

- 内置中英文常用字段目录，结合 autocomplete、label、name、placeholder、帮助文字、章节和邻近字段进行归一与相似度匹配。
- 用户自定义字段别名会参与后续匹配，使信息库能够超出内置目录继续增长。
- 同类结构化资料存在多条时不再按序号静默选择，而是展示整条候选记录；同一组公司/岗位/时间/工作内容或项目字段只能来自用户选中的同一条记录。
- 唯一、高置信且网页为空的普通文本字段可直接填写；选择控件、证件/出生日期等敏感字段、长文本和低置信匹配必须确认。网页已有内容默认不覆盖。
- 下拉选项保存显示文本而非站点私有 ID，回填时会打开控件并选择同名选项，最多等待约 1.2 秒处理异步选项。
- 新增 Web Agent 工具：
  - `browser.remember_current_form`
  - `browser.fill_current_form`
- 两个工具均支持有模型工具调用与无模型安全降级路径。
- 填写支持一次性本地会话与预览模式；确认面板区分已填写、待选择、待确认、已有内容和资料缺失，并支持临时填写、存入资料库、忽略和以后处理。
- 实际填写只派发 input/change 事件，不点击提交按钮，并明确返回 `submitted: false`。

### 4. 独立个人信息页面

- 悬浮球右键菜单的“个人信息”预留入口已接通独立 `personal-info` 窗口，不占用设置页面。
- 按分类展示信息及来源；聊天推断项展示置信度和“待确认”状态。
- 页面采用贴边白色画布，左侧分类导航覆盖全部业务分类、待确认资料与填写记忆，并显示各分类数量。
- 支持新增多字段关联记录、字段级编辑/删除、整条记录删除，以及填写记忆的查看、修改和删除。
- 后端新增个人资料、关联记录、填写记忆与一次性填写会话 API。

## 数据与安全策略

- 数据仅进入现有本地 SQLite 数据库。
- API 密钥、认证秘密通过现有 `contains_secret` 策略再次拦截。
- 密码、验证码、文件、支付卡信息在扩展侧不采集。
- 候选实际值只存放在 30 分钟有效的本地填写会话中；Agent observation 仅包含会话 ID和分类计数，不会把个人资料值发送给语义模型。
- 聊天自动增长采用“先提案、后确认”，不会静默覆盖用户已确认资料。
- 填写动作需要用户提出表单填写/预览指令，工具按中风险动作进行确认解析。
- 扩展默认只写空字段；替换已有内容必须携带用户确认和预览时的原值，两者任一不匹配即跳过。
- 本功能不负责提交表单，避免造成不可逆的外部操作。

## 使用方式

1. 重新构建并在 Chrome/Edge 中加载 `browser-extension/dist`。
2. 用户填写网页后说：“记住这个表单中所填的内容”。
3. 以后在相似表单页面说：“帮我填页面的表单”；如需先检查，使用“先预览能填写哪些字段”。
4. 在确认面板中为多条经历选择整条记录，确认敏感项或长文本；可勾选“记住本次选择和修改”。
5. 右键悬浮球并打开“个人信息”，维护资料记录、待确认项和填写记忆。

## 已知边界

- 当前语义目录重点覆盖第一阶段的身份、联系、地址、教育、工作/实习、项目、技能、证书、获奖和常用开放题；行业专用字段会作为自定义资料保存，并通过确认别名参与后续匹配。
- 跨域 iframe 内的表单受浏览器同源策略限制，当前不采集。
- 级联选择器需要站点逐级选项文本一致；页面尚未创建的第二/第三条经历区域不会自动点击“新增经历”，需要页面先存在对应记录区域再选择资料回填。
- 本次自动化验证覆盖后端、扩展编译和前端浏览器 E2E；真实业务站点仍可能因封闭 Shadow DOM 或定制控件需要增加适配器。
