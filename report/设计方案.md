# DeskPilot 桌面浮层 UI 设计方案

## 1. 文档目标

本文档基于 `frontend/design/设计图.png` 和 DeskPilot 当前技术架构，定义第一版桌面浮层交互与界面设计标准。该方案用于指导后续产品设计、Tauri 窗口实现、React 组件拆分、后端事件展示和验收测试。

DeskPilot 的第一版 UI 不再定义为传统“固定悬浮窗”，而是定义为：

```text
桌面悬浮球 + 全屏透明 Overlay + 底部 AI 命令框 + 上下文推荐操作 + 设置窗口
```

核心体验是：用户平时只看到一个不打扰工作的悬浮球；需要 AI 帮助时点击悬浮球，当前屏幕覆盖一层从下往上的透明渐变，底部出现对话框和推荐操作；用户输入自然语言或点击推荐操作后，系统展示任务执行过程和结果。

## 2. 产品定位

DeskPilot 是一个 Windows 桌面级 AI 操作入口，不是普通聊天软件，也不是后台管理系统。

产品目标：

- 降低用户从当前工作场景切换到 AI 工具的成本。
- 基于当前网页、当前窗口、屏幕内容和历史偏好推荐可执行操作。
- 将自然语言任务转化为受控的浏览器、文件、桌面自动化和 RPA 操作。
- 在任务执行过程中持续向用户展示进度、风险确认和结果。

一句话定义：

```text
DeskPilot 是覆盖在当前桌面之上的 AI 命令面板。
```

## 3. 设计原则

### 3.1 不打断当前工作

悬浮球常驻但低存在感。Overlay 打开后，上半屏保持高度透明，用户仍能感知原桌面内容，避免产生“被新窗口接管”的感觉。

### 3.2 命令输入优先

底部对话框是主入口，任何状态下都应优先保证输入框可见、可聚焦、可发送、可取消。

### 3.3 上下文明确

用户必须知道 DeskPilot 当前能看到什么，例如当前网页、当前窗口、截图识别或无可用上下文。涉及网页内容、截图、聊天记录、文件读写等敏感能力时，应明确提示权限范围。

### 3.4 过程可见，风险可控

AI 执行任务时必须展示关键步骤、工具调用、等待确认、完成结果和失败原因。不能只显示“正在思考”。

### 3.5 小而完整

第一版不追求复杂功能入口，优先完成悬浮球、Overlay、推荐操作、任务执行、设置窗口这条主链路。

## 4. 核心界面结构

根据设计图，第一版包含四个一级界面：

```text
1. 悬浮球与右键菜单
2. 点击悬浮球后的全屏 Overlay
3. 任务执行 Overlay
4. 设置页面
```

整体状态关系：

```text
应用启动
  -> 显示悬浮球
  -> 左键点击悬浮球
  -> 打开全屏 Overlay
  -> 输入指令或点击推荐操作
  -> 进入任务执行状态
  -> 展示完成、失败或等待确认
  -> 关闭 Overlay，回到悬浮球

悬浮球
  -> 右键菜单
  -> 设置 / 个人信息 / 退出
  -> 打开设置窗口
```

## 5. 界面一：悬浮球与右键菜单

### 5.1 设计目标

悬浮球是 DeskPilot 的常驻入口。它应当足够明显，便于用户随时打开；同时不能遮挡当前工作内容。

### 5.2 布局

默认悬浮球：

```text
圆形按钮
默认吸附屏幕右侧
支持拖拽
支持 hover 反馈
支持右键菜单
```

推荐尺寸：

| 状态 | 尺寸 |
|---|---|
| 默认 | 48 x 48px |
| 紧凑 | 40 x 40px |
| Hover 展开 | 96-128 x 48px |
| 拖拽中 | 48 x 48px，透明度提高 |

推荐位置：

```text
初始位置：屏幕右侧中部
边距：16px
拖拽释放后：自动吸附到左侧或右侧
```

### 5.3 视觉规范

悬浮球样式：

```text
形状：圆形
背景：半透明深色或品牌渐变
图标：DeskPilot 标识或简化 D 标识
阴影：中等桌面阴影
边框：1px 半透明高光
```

状态样式：

| 状态 | 表现 |
|---|---|
| 空闲 | 普通圆球 |
| Hover | 放大 4%，提高不透明度 |
| 拖拽 | 跟随鼠标，显示吸附边缘提示 |
| 执行中 | 圆球外圈显示旋转或进度 |
| 等待确认 | 黄色脉冲点 |
| 失败 | 红色小点 |
| 成功 | 绿色短暂闪烁后恢复 |

### 5.4 交互

| 操作 | 结果 |
|---|---|
| 左键单击 | 打开全屏 Overlay |
| 右键单击 | 打开右键菜单 |
| 拖拽 | 移动悬浮球 |
| 拖拽释放 | 吸附最近屏幕边缘 |
| Hover | 显示 tooltip：打开 DeskPilot |

右键菜单项目：

```text
设置
个人信息
任务历史
暂停悬浮球
退出 DeskPilot
```

第一版可先实现：

```text
设置
个人信息
退出 DeskPilot
```

### 5.5 实现要求

Tauri 侧建议把悬浮球做成独立窗口：

```text
window label: floating-ball
alwaysOnTop: true
decorations: false
transparent: true
resizable: false
skipTaskbar: true
```

窗口尺寸只覆盖悬浮球和菜单区域，避免无意义拦截鼠标事件。

## 6. 界面二：点击后的全屏 Overlay

### 6.1 设计目标

Overlay 是用户主要操作界面。它不是完整应用窗口，而是覆盖当前屏幕的一层临时命令面板。

设计图中的关键元素：

```text
左上角：点击后状态标题
右上角：关闭按钮和关闭提示
中下部：根据识别视窗信息推荐操作
底部中间：对话框
```

### 6.2 布局

全屏结构：

```text
┌────────────────────────────────────┐
│ 点击后                 点击按钮处或空白处关闭  X │
│                                    │
│                                    │
│                                    │
│          根据识别的视窗信息推荐操作       │
│             [推荐1] [推荐2] [推荐3]      │
│                                    │
│              ┌────────────────┐     │
│              │ 输入你想做的事... │     │
│              └────────────────┘     │
└────────────────────────────────────┘
```

推荐尺寸：

| 元素 | 规格 |
|---|---|
| Overlay | 当前屏幕全尺寸 |
| 输入框容器宽度 | `min(720px, 100vw - 48px)` |
| 输入框高度 | 56-72px |
| 输入框底部距离 | 48-80px |
| 推荐操作距离输入框 | 16-24px |
| 关闭按钮 | 32 x 32px |

### 6.3 背景遮罩

Overlay 背景应从下往上渐变，底部承载操作区，上半部分尽量透明。

推荐 CSS：

```css
.desktop-overlay {
  background:
    linear-gradient(
      to top,
      rgba(8, 12, 20, 0.72) 0%,
      rgba(8, 12, 20, 0.48) 28%,
      rgba(8, 12, 20, 0.18) 58%,
      rgba(8, 12, 20, 0.03) 100%
    );
  backdrop-filter: blur(4px);
}
```

注意事项：

- 上半屏不要过暗，避免用户失去当前桌面方位感。
- 底部可以更暗，保证输入框和推荐操作可读。
- Windows WebView 对 `backdrop-filter` 支持需要实际验证，必要时降级为纯透明渐变。

### 6.4 顶部提示与关闭

左上角显示当前 Overlay 状态：

```text
DeskPilot
已识别当前网页
```

右上角显示关闭提示：

```text
点击空白处或 Esc 关闭
```

关闭按钮：

```text
X 图标
点击关闭 Overlay
```

关闭方式：

| 操作 | 结果 |
|---|---|
| 点击关闭按钮 | 关闭 Overlay |
| 按 Esc | 关闭 Overlay |
| 点击上方空白区域 | 关闭 Overlay |
| 点击输入区、推荐操作、任务面板 | 不关闭 |

### 6.5 推荐操作区

推荐操作来自当前上下文识别。

推荐操作区文案：

```text
根据当前视窗推荐操作
```

按钮样式：

```text
胶囊按钮
高度 32-36px
圆角 999px
最多显示 4 个
宽度自适应文字
```

浏览器网页场景：

```text
总结当前网页
提取表格
保存为 Markdown
翻译页面
```

普通桌面窗口场景：

```text
截图识别
解释当前界面
提取屏幕文字
生成操作建议
```

文件/文档场景：

```text
总结文档
提取重点
改写内容
生成大纲
```

无上下文场景：

```text
打开应用
整理文件
搜索网页
创建笔记
```

推荐优先级：

```text
1. 当前浏览器网页 URL、标题、DOM 摘要
2. 当前前台窗口进程名和标题
3. 当前屏幕 OCR 或截图内容
4. 用户历史常用操作
5. 默认通用操作
```

### 6.6 底部对话框

输入框是主控件。

结构：

```text
┌────────────────────────────────────┐
│ 上下文图标  输入你想让 DeskPilot 做什么...  发送 │
└────────────────────────────────────┘
```

交互规则：

| 操作 | 结果 |
|---|---|
| Overlay 打开 | 输入框自动聚焦 |
| Enter | 发送任务 |
| Shift + Enter | 换行 |
| Esc | 关闭 Overlay |
| 输入超过一行 | 自动增高，最多 5 行 |
| 执行中 | 发送按钮变为停止按钮 |

占位文案：

```text
输入你想让 DeskPilot 做的事...
例如：总结当前网页并保存为 Markdown
```

## 7. 界面三：任务执行 Overlay

### 7.1 设计目标

任务执行时，用户需要看到 AI 正在做什么、已完成什么、是否卡住、是否需要确认。

设计图中任务执行页的核心元素：

```text
左上角：任务执行
右侧：任务步骤列表
底部：显示 AI 思考过程或任务事件
```

### 7.2 布局

任务执行状态建议复用 Overlay，不打开新的普通窗口。

结构：

```text
┌────────────────────────────────────┐
│ 任务执行                            │
│                                    │
│                  正在做什么 1  [状态] │
│                                    │
│                  正在做什么 2  [状态] │
│                  ……                │
│                                    │
│              显示 AI 思考过程         │
│          ┌────────────────────┐      │
│          │ 当前工具事件 / 结果摘要 │      │
│          └────────────────────┘      │
└────────────────────────────────────┘
```

### 7.3 任务步骤展示

每个步骤对应后端 SSE 事件。

事件映射：

| 后端事件 | UI 展示 |
|---|---|
| `task.created` | 已创建任务 |
| `task.started` | 开始执行 |
| `task.plan.updated` | 更新计划 |
| `tool.started` | 正在执行工具 |
| `tool.finished` | 工具完成 |
| `approval.required` | 等待用户确认 |
| `task.completed` | 任务完成 |
| `task.failed` | 任务失败 |
| `task.cancelled` | 已取消 |

步骤状态：

```text
pending   未开始
running   正在执行
success   已完成
warning   等待确认
error     失败
cancelled 已取消
```

视觉表现：

| 状态 | 样式 |
|---|---|
| pending | 灰色圆点 |
| running | 蓝色旋转点 |
| success | 绿色对勾 |
| warning | 黄色提示 |
| error | 红色错误 |
| cancelled | 灰色中止 |

### 7.4 AI 思考过程展示

底部“显示 AI 思考过程”不应展示原始模型 chain-of-thought。产品上应展示“可解释的执行过程”，包括计划、工具调用和观察摘要。

推荐命名：

```text
执行过程
```

可展示内容：

```text
正在读取当前网页
已获取页面标题和正文
正在生成摘要
正在写入 Markdown 文件
已保存到 data/exports/xxx.md
```

不展示内容：

```text
模型内部推理链
隐藏系统提示词
完整网页正文
敏感聊天记录全文
API Key 或本地路径敏感信息
```

### 7.5 完成状态

完成后展示结果卡片：

```text
任务已完成
摘要已生成，并保存到本地 Markdown 文件。

[打开文件] [复制结果] [继续追问]
```

结果应支持 artifact：

```text
文件
表格
截图
网页摘要
错误日志
```

### 7.6 失败状态

失败后展示原因和下一步：

```text
任务执行失败
无法读取当前网页内容，浏览器扩展可能未连接。

[重试] [查看详情] [手动粘贴内容]
```

失败信息必须来源于结构化错误：

```text
error.code
error.message
error.detail
```

### 8.7 快捷键设置

字段：


### 8.8 上下文权限


权限展示要求：

- 明确说明每项权限用途。
- 标识自动执行、每次询问、禁用三种策略。
- 高风险权限默认每次询问。

### 9.5 动效

动效应短、轻、可预测。

| 场景 | 动效 |
|---|---|
| 悬浮球 Hover | 120ms scale + opacity |
| Overlay 打开 | 160ms fade in + bottom content translateY |
| Overlay 关闭 | 120ms fade out |
| 推荐按钮出现 | 120ms stagger fade |
| 任务步骤新增 | 160ms slide up |
| 等待确认 | 1.2s pulse |

避免使用复杂弹跳、大幅缩放、过度发光。

## 12. 与后端能力的映射

UI 动作映射：

| UI 操作 | 后端动作 |

| 打开 Overlay | 获取当前窗口和浏览器上下文 |

## 15. 验收标准

### 15.1 悬浮球

- 应用启动后显示悬浮球。
- 悬浮球不出现在任务栏。
- 悬浮球可点击打开 Overlay。
- 右键可打开菜单。
- 菜单中可进入设置页面。

### 15.2 Overlay

- Overlay 覆盖当前屏幕。
- 背景为从下往上的透明渐变。
- 底部输入框居中显示并自动聚焦。
- 推荐操作显示在输入框上方。
- 点击关闭按钮、按 Esc、点击空白区域均可关闭。
- 点击输入框、推荐操作、任务面板不会误关闭。

### 15.3 任务执行

- 发送任务后调用 `POST /chat`。
- UI 能接收并展示 `GET /events` 的 SSE 事件。
- 至少区分运行中、完成、失败、取消四种状态。
- 执行中可以停止任务。
- 完成后显示结果摘要或 artifact。

### 15.4 设置页

- 右键菜单可以打开设置窗口。
- 设置窗口包含左侧导航和右侧内容区。
- 至少包含账号、通用、悬浮球、权限、AI 设置、关于。

### 15.5 可用性

- Overlay 打开反馈应在 150ms 左右出现。
- 输入框文字在 720px 宽度内可读。
- 推荐按钮最多显示 4 个，超出时折叠或横向滚动。
- 所有重要按钮有 hover、active、disabled 状态。
